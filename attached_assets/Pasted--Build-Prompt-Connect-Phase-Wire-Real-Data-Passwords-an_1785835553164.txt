# Build Prompt — Connect Phase: Wire Real Data, Passwords, and Email

Copy into Replit. This connects the 4 screens already built (Dashboard, Collection Detail, Create New Collection, Unlock Email template) to real Firebase data and real email sending via Resend, replacing all mock data and simulated actions.

## Environment variables to set up first (Replit Secrets, not hardcoded)

- `FIREBASE_SERVICE_ACCOUNT_KEY` — paste the full contents of the downloaded service account JSON file as a single value
- `RESEND_API_KEY` — your Resend API key
- `RESEND_FROM_EMAIL` — for now, use `onboarding@resend.dev`; will be swapped once a Nynth domain is verified

Never commit these to the repo. If a `.env` file is used locally, make sure it's in `.gitignore`.

## Firestore schema (final)

```
collections/{slug}              <- document ID IS the slug, no separate slug field
  name: string
  launchDatetime: timestamp
  status: "locked" | "live"

collections/{slug}/signups/{signupId}   <- subcollection, scoped per collection
  email: string
  password: string | null       <- null until emails are sent
  unlocked: boolean             <- false until emails are sent
  createdAt: timestamp
```

Signups arrive here from the real site's own signup form (separate codebase, not built in this prompt) writing directly into `collections/{slug}/signups`.

## Server-side setup

Initialize the Firebase Admin SDK once, server-side only (e.g. `lib/firebaseAdmin.ts`), using `FIREBASE_SERVICE_ACCOUNT_KEY`. This has full read/write access — never expose it to client-side code.

Initialize Resend once, server-side only, using `RESEND_API_KEY`.

## Functions to build

1. **`getCollections()`** — reads all documents from `collections`, including a live count of each one's `signups` subcollection size. Powers the Dashboard.

2. **`getCollection(slug)`** and **`getSignups(slug)`** — reads one collection's data and its full signups list. Powers Collection Detail.

3. **`createCollection({ name, slug, launchDatetime })`** — writes a new document to `collections` using the provided slug as the document ID. Reject the write if a document with that slug already exists (this is what makes slugs unique and enforces the "immutable after creation" rule — there's simply no update path for the slug/ID, only creation). Powers Create New Collection.

4. **`sendUnlockEmails(slug)`** — the core function. For the given collection:
   - Fetch all signups where `unlocked == false`
   - For each one, generate a unique password (use a cryptographically random string, e.g. `crypto.randomBytes(6).toString('hex')` or similar — readable enough to type, random enough to be secure)
   - Update that signup's Firestore document: set `password` and `unlocked: true`
   - Send an email via Resend using the Screen 4 template, passing in `collectionName`, the generated `password`, and an `unlockUrl` pointing to the real site's collection page (`https://[real-site-domain]/[slug]`)
   - Do this as a batch/loop with error handling per signup — if one email fails to send, don't let it block the rest; collect failures and surface them in the response
   - Return a summary: how many sent successfully, how many failed

## Wire each screen

- **Dashboard** → replace the mock array with `getCollections()`
- **Collection Detail** → replace mock data with `getCollection(slug)` + `getSignups(slug)`; wire the "Send Unlock Emails" button to call `sendUnlockEmails(slug)` for real, show the real success/failure summary instead of the mock banner, and refresh the signup list afterward so unlocked statuses reflect reality
- **Create New Collection** → wire the form submit to `createCollection(...)`; on success, show the real confirmation state; on slug-already-exists error, show a clear inline error instead of the generic mock success
- **Unlock Email template** → no wiring needed here, it's already being called by `sendUnlockEmails()` with real data

## Explicitly out of scope for this prompt

- Anything in the real site's codebase — that's separate work, noted below
- A login/auth screen for this admin tool itself (still assuming trusted access for now)

## Deliverable

All 4 screens running on real Firestore data, with "Create Collection" and "Send Unlock Emails" performing real writes and a real email actually arriving in the inbox used to sign up for Resend.

## Flag for the real site's codebase (not part of this prompt)

The real site's unlock gate currently has nothing to check a password against. It needs a function that, given an email + entered password for a given collection slug, queries `collections/{slug}/signups` for a matching `email` + `password` pair and grants access if found. This should run server-side (not a raw client-side Firestore read of the signups subcollection, which would risk exposing other users' emails/passwords) — a Cloud Function or a server action in the real site's own backend is the right shape for it.
